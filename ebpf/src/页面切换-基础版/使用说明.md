# TracePilot 使用指南

## 概述

TracePilot 是一个基于 eBPF + Perfetto 的 Frame-Centric 调度观测系统，用于定位 Android App 页面切换时的卡顿根因。

以 Perfetto 帧窗口为标尺，将 eBPF 采集的调度事件投射到每个卡顿帧的时间窗口内，按线程聚合后计算评分并输出 top-k 关键线程。

```
Perfetto ──→ trace ──→ trace_processor_shell ──→ frames.txt
eBPF 7×tp/ raw tp ──→ events.bin (v2) ──→ run_analysis.py ──→ result_py.json
```

## 环境要求

### 设备端（Pixel 6a）
- Android 15 (kernel 6.1)，已 root
- Perfetto 已内置
- BTF 可用（`/sys/kernel/btf/vmlinux` 存在）

### 编译环境（WSL Ubuntu）
```bash
sudo apt install clang gcc libbpf-dev libelf-dev zlib1g-dev
```
- NDK r26b：`~/pixel6a-bpf/third_party/android-ndk-r26b`
- libbpf：`~/pixel6a-bpf/页面切换-基础版/libbpf`

### 分析环境（Windows）
- Python 3.x（无需额外依赖）

## 编译

```bash
# 在 WSL 中
cd ~/pixel6a-bpf/页面切换-基础版
make bpf && make android
```

编译产物：
| 文件 | 用途 |
|------|------|
| `output/tracepilot.bpf.o` | eBPF 字节码 |
| `output/tracepilot-aarch64` | 设备端 loader（aarch64 静态二进制） |

## 采集流程

### 1. 配置 Perfetto

编辑 `scripts/perfetto_config.pbtx`，将 `<PKG>` 替换为目标 App 包名：

```
QQ:       com.tencent.mobileqq
微信:     com.tencent.mm
小红书:   com.xingin.xhs
抖音:     com.ss.android.ugc.aweme
```

每次只能测一个 App（避免多 App 共享缓冲区导致 atrace 覆盖不均）。

### 2. 推送二进制（WSL 编译后）

```bash
# WSL → Windows 同步
cp output/tracepilot.bpf.o output/tracepilot-aarch64 /mnt/d/osh大作业/页面切换-基础版/output/
cp scripts/perfetto_config.pbtx /mnt/d/osh大作业/页面切换-基础版/scripts/
```

### 3. 推送至设备（Windows PowerShell）

```powershell
cd "D:\osh大作业\页面切换-基础版"

adb push output\tracepilot-aarch64 /data/local/tmp/tracepilot
adb push output\tracepilot.bpf.o /data/local/tmp/
adb push scripts\perfetto_config.pbtx /data/local/tmp/
adb shell "su -c 'chmod +x /data/local/tmp/tracepilot'"
```

### 4. 启动采集

```powershell
# 两个命令先后执行即可（Perfetto --background 不阻塞，loader 后台运行 60s）
adb shell "perfetto --txt -c /data/local/tmp/perfetto_config.pbtx -o /sdcard/perfetto_trace.perfetto-trace --background"
adb shell "su -c '/data/local/tmp/tracepilot -d 60 -e /data/local/tmp/events.bin -D'"
```

### 5. 切换页面

在手机上操作目标 App，切换页面，等 60 秒。

> **建议关闭其他后台 App**：
> ```powershell
> adb shell am force-stop com.xingin.xhs
> adb shell am force-stop com.tencent.mm
> ```

### 6. 拉取数据

```powershell
adb pull /sdcard/perfetto_trace.perfetto-trace output\
adb pull /data/local/tmp/events.bin output\tracepilot_events.bin
```

### 7. 提取帧数据（WSL）

```bash
/mnt/d/osh大作业/页面切换-基础版/output/linux-amd64/trace_processor_shell \
  -q /mnt/d/osh大作业/页面切换-基础版/scripts/frame_query.sql \
  /mnt/d/osh大作业/页面切换-基础版/output/perfetto_trace.perfetto-trace \
  > /mnt/d/osh大作业/页面切换-基础版/output/frames.txt
```

### 8. 运行分析（Windows PowerShell）

```powershell
python output\run_analysis.py
```

结果写入 `output/result_py.json`，摘要写入 `output/py_success.txt`。

## 输出解读

```json
{
  "total_frames": 230,
  "jank_frames": 220,
  "jank_system_overhead_ns": 3371925849,
  "top_k_threads": [
    {
      "rank": 1,
      "tid": 12649,
      "pid": 0,
      "comm": "single-pool-def",
      "package": "",
      "score": 0.3692,
      "runnable_delay_p95_ns": 1382163045,
      "wakeup_latency_p95_ns": 1382280884,
      "system_overhead_ns": 1063077117
    }
  ]
}
```

| 字段 | 含义 |
|------|------|
| `total_frames` | 总帧数 |
| `jank_frames` | 卡顿帧数 |
| `jank_system_overhead_ns` | 卡顿帧中 IRQ+SoftIRQ 累计 |
| `comm` | 线程名（从 wakeup 事件映射填充） |
| `score` | 综合评分（已扣除系统开销） |
| `runnable_delay_p95_ns` | 被抢占后在运行队列等待的 p95 时间 |
| `wakeup_latency_p95_ns` | 从唤醒到获得 CPU 的 p95 时间 |
| `system_overhead_ns` | 该线程参与帧中的累计中断/软中断耗时 |

## 评分公式

```
base_score = 0.35 × J + 0.35 × log1p(rd_ms) + 0.15 × log1p(wl_ms) + 0.15 × UI

J     = 参与卡顿帧数 / 总卡顿帧数
rd_ms = runnable_delay_p95_ns / 1e6
wl_ms = wakeup_latency_p95_ns / 1e6
UI    = 1 (若 comm 含 "RenderThread" 或 ".ui")

sys_ratio = 每帧平均系统开销 / 16.67ms
score     = base_score × (1.0 - min(sys_ratio, 0.9))
```

## Perfetto Trace 深度查询

分析工具只给出评分排名。要进一步定位根因，需直接查询 Perfetto trace：

```bash
TP="/mnt/d/osh大作业/页面切换-基础版/output/linux-amd64/trace_processor_shell"
TRACE="/mnt/d/osh大作业/页面切换-基础版/output/perfetto_trace.perfetto-trace"

# 查所有 App 的 atrace 活动量
$TP $TRACE -Q "SELECT p.name, COUNT(*) FROM slice s JOIN thread_track tt ON s.track_id=tt.id JOIN thread t ON tt.utid=t.id JOIN process p ON t.upid=p.upid WHERE p.name LIKE 'com.%' GROUP BY p.name ORDER BY COUNT(*) DESC"

# 查某线程的阻塞状态分布
$TP $TRACE -Q "SELECT t.name, t.tid, s.end_state, COUNT(*), ROUND(AVG(s.dur)/1e6,2) FROM sched_slice s JOIN thread t ON s.utid=t.id WHERE s.end_state IS NOT NULL AND t.tid=19046 GROUP BY s.end_state ORDER BY COUNT(*) DESC"

# 查 GPU 渲染瓶颈
$TP $TRACE -Q "SELECT name, COUNT(*), ROUND(AVG(dur)/1e6,2), ROUND(MAX(dur)/1e6,1) FROM slice WHERE name LIKE '%GPU%' OR name LIKE '%OpsTask%' GROUP BY name ORDER BY COUNT(*) DESC"

# 查关键线程 CPU 时间
$TP $TRACE -Q "SELECT t.name, t.tid, ROUND(SUM(s.dur)/1e9,2), COUNT(*) FROM sched_slice s JOIN thread t ON s.utid=t.id WHERE s.dur>0 AND t.tid IN (19046,699,678) GROUP BY t.tid ORDER BY SUM(s.dur) DESC"
```

## 故障排查

| 问题 | 排查 |
|------|------|
| BPF 加载失败 | `adb shell "su -c 'dmesg \| grep -i bpf'"` |
| events.bin 为空 | 确认 root 权限、BTF 可用 |
| frames.txt 为空 | 确认 Perfetto 配置含 gfx atrace |
| rd 全为零 | 确认 `prev_state & 0xFF == 0` 已修复并重新编译推送 |
| top_k_threads 为空 | 确认 eBPF 和 Perfetto 同一轮采集 |
| 某 App atrace 极少 | `atrace_apps: "*"` 改单包名，buffer 扩至 128MB |
| 包名为空 | 离线模式正常（无 device 端 pm 命令） |
| trace_processor_shell 报错 | 用本地预编译版 `output/linux-amd64/trace_processor_shell` |
