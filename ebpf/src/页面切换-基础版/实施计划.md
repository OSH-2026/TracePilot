# TracePilot 实施计划

## 项目上下文

- **设备**: 已 root 的 Pixel 6a, Android 15 (kernel 6.1), 支持 BTF/CO-RE
- **框架**: libbpf 原生 API（`bpf_object__open_file()` 等），不依赖 bpftool skeleton
- **BPF hook 方式**: 全部 `tp/` raw tracepoint — sched_switch / sched_wakeup / irq / softirq
- **编译环境**: WSL Ubuntu（`~/pixel6a-bpf/`），NDK r26b（android34-clang）
- **测试场景**: 多 App 页面切换（QQ / 微信 / 小红书 / 抖音 / 汽水音乐）
- **vmlinux.h**: 已从 Pixel 6a 提取

## BPF Maps 总览

| Map | 类型 | 大小 | 用途 |
|-----|------|------|------|
| `events` | RINGBUF | 16MB | sched_switch / sched_wakeup 事件输出 |
| `sys_events` | RINGBUF | 4MB | IRQ / SoftIRQ 系统事件输出 |
| `wakeup_times` | HASH | 10240 | tid → 唤醒时间戳 |
| `preempt_times` | HASH | 10240 | tid → 抢占时间戳（计算 runnable_delay） |
| `irq_start_times` | HASH | 256 | (cpu<<32\|irq) → IRQ entry 时间戳 |
| `softirq_start_times` | HASH | 64 | (cpu<<32\|vec) → SoftIRQ entry 时间戳 |

## 架构

```
设备端（Pixel 6a）                     宿主机（Windows / WSL）
─────────────────                     ─────────────────────
Perfetto ──→ trace.perfetto-trace ──→ trace_processor_shell ──→ frames.txt
eBPF loader ──→ events.bin (v2) ────→ run_analysis.py ──→ result_py.json
  ├─ sched_switch      (tp/sched/sched_switch, events ringbuf)
  ├─ sched_wakeup      (tp/sched/sched_wakeup, events ringbuf)
  ├─ irq_handler_entry (tp/irq/irq_handler_entry, sys_events ringbuf)
  ├─ irq_handler_exit  (tp/irq/irq_handler_exit, sys_events ringbuf)
  ├─ softirq_entry     (tp/irq/softirq_entry, sys_events ringbuf)
  └─ softirq_exit      (tp/irq/softirq_exit, sys_events ringbuf)
```

- 设备端：Perfetto 采 gfx/view/am/wm/res/dalvik atrace + 调度 ftrace + GPU ftrace
- 宿主机：Python `run_analysis.py` 替代 C loader 做离线分析
- 时钟对齐：eBPF (CLOCK_MONOTONIC) → Perfetto (CLOCK_BOOTTIME)，自动检测偏移

## 评分模型

```
base_score = 0.35 × J + 0.35 × log1p(rd_ms) + 0.15 × log1p(wl_ms) + 0.15 × UI

J     = jank_frame_count / num_jank
rd_ms = runnable_delay_p95_ns / 1e6
wl_ms = wakeup_latency_p95_ns / 1e6
UI    = 1 if comm contains "RenderThread" or ".ui"

sys_ratio = avg_sys_overlap / 16666666.0
score     = base_score × (1.0 - min(sys_ratio, 0.9))
```

## 实施任务

### Task 1: 环境准备 — 完成
- vmlinux.h 从 Pixel 6a 提取
- NDK r26b 位于 `~/pixel6a-bpf/third_party/android-ndk-r26b`
- libbpf 位于 `~/pixel6a-bpf/页面切换-基础版/libbpf`
- Perfetto 预编译工具在 `output/linux-amd64/`

### Task 2: eBPF 程序 — 完成
- 7 个 raw tracepoint（全部 `tp/`，非 tp_btf）
- **sched_switch 结构体修正**：vmlinux.h 中 `prev_state` 误标为 `long`（8 字节），Android 6.1 内核实际为 `unsigned int`（4 字节），导致后续字段偏移错误。添加本地 `struct sched_switch_raw_tp` 使用正确布局
- **runnable_delay 跟踪**：`preempt_times` map 追踪抢占→重新调度延迟，`prev_state & 0xFF == 0` 判断 TASK_RUNNING（内核会设置 TASK_REPORT_IDLE 标志 0x0100）
- comm 读取：`__builtin_memset` 清零 + `bpf_probe_read_kernel_str`
- 6 个 maps：2 个 RINGBUF + 4 个 HASH

### Task 3: 用户态 Loader — 完成
- 原生 libbpf API：`bpf_object__open_file()` + `bpf_object__load()` + `bpf_program__attach()`
- 双 ring_buffer 轮询
- v2 文件格式（含 sched + sys events）

### Task 4: Python 离线分析工具 — 完成
- `output/run_analysis.py` 替代 C loader 做分析（修复了 C 版的多项 bug）
- set 去重替代 last_token 单值去重
- 帧窗口反转处理（actual_present < expected_start）
- 噪声过滤（shell svc / tracepilot / dwc3 / adbd / UsbFfs）
- TID→comm 映射（从 wakeup 事件填充 switch 事件）
- p95 计算 runnable_delay 和 wakeup_latency

### Task 5: Perfetto 配置 — 完成
- 128MB 缓冲区
- atrace: gfx + view + am + wm + res + dalvik
- ftrace: sched_switch/wakeup + irq + softirq + GPU (gpu_work_period/gpu_frequency) + block I/O + f2fs
- 单 App 模式（atrace_apps 改为目标包名，避免多 App 缓冲区竞争）
- 采集时长 60s

### Task 6: 多 App 测试方案 — 完成
- 每个 App 单独采集（改 atrace_apps 包名），各采 60s
- 采集时关闭其他后台 App
- 对比各 App 的 jank_frames 和 RenderThread wl

## Bug 修复记录

| 问题 | 修复 |
|------|------|
| sched_switch comm 乱码 | 添加本地 `struct sched_switch_raw_tp`（prev_state 改为 unsigned int） |
| runnable_delay 全为 0 | `prev_state == 0` → `(prev_state & 0xFF) == 0`（兼容 TASK_REPORT_IDLE 标志） |
| top_k_threads 为空 | 帧窗口反转处理（负延迟帧） |
| jank_count 膨胀 | last_token → set 去重 |
| C loader 输出乱码 | Python 工具替代，UTF-8 编码 |
| atrace 覆盖不均 | atrace_apps 改为单包名，buffer 扩至 128MB |
| GPU 事件名不匹配 | mali/* → gpu/gpu_work_period |
| Binder ftrace 不可用 | 从配置移除（Pixel 6a 内核不支持） |
| include 路径错误 | `libbpf/src/libbpf.h` → 条件编译 `<bpf/libbpf.h>` / `"libbpf.h"` |

## 已知局限性

| 限制 | 说明 |
|------|------|
| eBPF 与 Perfetto TID 不同步 | 两次采集的 fork 时序不同，TID 可能偏移 |
| IRQ name 未采集 | system_event 不含 IRQ 名称 |
| 系统事件跨帧不裁剪 | duration 全部计入 exit 时间戳所在帧 |
| 离线模式无包名 | pm 命令仅设备端可用 |
| hash map 可能溢出 | irq_start_times(256), softirq_start_times(64) |
| 多 App 需分开采集 | `atrace_apps: "*"` 导致缓冲区竞争 |
